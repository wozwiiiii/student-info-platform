## 1. 产品定位

**一句话**：面向单一学校试点、以低年级为核心用户的大学生信息收集与汇总数据中台——把分散在教务处、学生会、就业处、各学院等渠道的成长相关信息，聚合为结构化、可溯源、带截止提醒的统一入口，并以「成长路线图」帮助低年级学生从大一就开始规划四年。

### 1.1 核心决策总览（五轮问答结论）

| 轮次 | 决策项 | 结论 |
|---|---|---|
| 1 | 范围 / 用户 / 愿景 | 单校试点；低年级为主；从大一开始的全周期成长规划（含竞赛/保研/实习/就业） |
| 2 | 信息类别优先级 | 机会成长类 > 奖助评优类 > 学业教务类（通知转发）；讲座活动类可选 |
| 2 | 路线图 | 简版成长路线图进 MVP |
| 3 | 采集方式 | 公众号半自动监控 + 官网爬取 + 用户主动投稿；校内源当前无法触达 |
| 4 | 载体 / 账号 | 微信小程序（唯一载体，App/H5 远期）；微信授权登录 |
| 5 | 运营 / 审核 / 激励 | 单兵起步跑通；AI 辅助审核；荣誉体系激励 |

### 1.2 目标用户与痛点

| 用户群 | 核心痛点 | 产品回应 |
|---|---|---|
| 低年级（首批核心） | 不知道四年该做什么、关键节点有哪些 | 简版成长路线图【假设：学生有此需求且愿意用工具解决，上线验证】 |
| 高年级（全周期覆盖） | 机会信息口口相传，信息差=机会损失 | 结构化机会信息 + deadline 提醒 |
| 全体 | 信息分散、群消息淹没 | 统一信息流 + 分类频道 |

## 3. 产品原则

1. **中台优先，不是社区优先**
2. **信息质量 > 信息数量**：一条过期/错误信息的信任代价远大于少采集十条
3. **截止时间是第一公民**：deadline 类信息优先于纯资讯
4. **不做无来源信息**：每条信息可溯源（原文链接/来源渠道）
5. **成长视角**：信息组织服务「从大一规划四年」

## 4. 运营与信息可信机制（第 5 轮确认）

### 4.1 运营模式
- **MVP**：【已确认】创始人单兵跑通采集→审核→发布闭环，验证价值后再扩团队
- **演进路径**（客观建议）：单兵验证 → 招募 2-5 名同学志愿小团队 → 挂靠社团/学生会组织化运营（解决人员更替 R6）→ 学生信息员网络（解决院内信息缺口 R3）

### 4.2 审核机制（AI 辅助审核）
- AI 辅助结构化：自动提取标题/时间/截止日期等字段 + 预判类别与时效
- 人工抽检：发布前对关键字段（尤其**截止日期**）快速复核；AI 低置信度条目转人工
- 【客观风险提示】AI 提取可能出错（如截止日期识别错误），而错误 deadline 的信任代价高——因此「AI 辅助 + 关键字段人工复核」是底线，不建议完全无人审核
- 众包投稿：AI 预审（来源合法性/重复检测）+ 人工确认后入库

### 4.3 激励机制（荣誉体系起步）
- MVP：投稿者署名、贡献榜、电子证书等零成本荣誉激励
- 中期：综测/第二课堂学分对接（需校方支持，当前无校内关系，列为目标而非前提）

## 5. 风险清单（最终版，共 12 项）

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| R1 | 机会类信息无结构化公开源，数据获取是根本瓶颈 | 高 | 采集组合已定；投稿补缺 |
| R2 | 单兵运营产能上限低，采集/审核/路线图维护需持续投入 | 高 | MVP 验证最小信息集；尽早招募志愿小团队 |
| R3 | 校内源触达当前为零，校内机会信息（保研细则/学院实习）覆盖不到 | 高 | 投稿补缺；把「建立校内关系」列为最优先行动（见第 6 节） |
| R4 | ~~多校复用难度~~ | 已规避 | 单校试点 |
| R5 | 学生习惯群通知，迁移成本高 | 中 | deadline 提醒 + 路线图做价值锚点 |
| R6 | 学生团队毕业更替，可持续性弱 | 中 | 组织化挂靠路径；荣誉体系沉淀贡献文化 |
| R7 | P0 三线并进超出单兵产能 | 中 | MVP 聚焦竞赛+就业，保研公开政策兜底 |
| R8 | 路线图内容维护成本与过期风险 | 中 | 节点标注整理时间；关联实时信息流 |
| R9 | 公众号监控灰色方案合规与稳定性风险 | 中高 | 【客观事实：微信不开放读取能力】多方案冗余；定位为降级可运行而非核心依赖 |
| R10 | 官网爬取反爬/改版中断 | 低中 | 低频爬取 + 人工补录 |
| R11 | 提醒触达单通道（仅小程序订阅消息），触达率打折 | 中 | MVP 验证触达数据；V1 候补公众号/群机器人 |
| R12 | **AI 辅助审核的字段提取错误**（尤其截止日期） | 中 | 关键字段人工复核；低置信度转人工；错误快速纠错通道 |

## 6. 下一步行动建议（按优先级）

1. **最小验证（建议先于开发）**：花 1-2 周用人工方式（无需小程序）验证「信息聚合」价值——如先建一个信息群/共享文档，人工搬运结构化信息，观察同学是否真的使用、是否愿意投稿。成本最低地验证【假设】：痛点真实存在且产品形态有人要。
2. **校内关系破冰（与验证并行）**：从最轻的关系切入——联系就业处公众号运营者、学院辅导员、社团负责人，不求接口只求「信息转发授权」。这决定 R3 缺口的收敛速度。
3. **MVP 开发**：小程序 + 录入后台 + AI 结构化管线；信息类别按 P0 竞赛+就业先行。
4. **路线图冷启动**：先手工整理一份本校「四年成长节点表」（可参考公开的保研/竞赛/校招时间线），作为路线图 v1 内容底座。
5. **验证指标建议**（实事求是，不预设虚荣指标）：周活跃使用、deadline 提醒订阅率与打开率、投稿条数、信息纠错率、次月留存。
6. **待验证假设清单**（上线后重点观察）：低年级是否真用路线图；学生是否愿意投稿；灰色采集方案的实测稳定性；订阅消息触达率。

## 7. 已确认 / 假设 清单（最终版）

**已确认（五轮问答全部结论）**
- 单校试点；低年级为主；从大一即开始的成长规划愿景
- MVP 类别：机会成长类（先竞赛+就业）> 奖助评优类 > 教务通知转发；讲座活动可选
- 简版成长路线图进 MVP
- 采集：公众号半自动监控 + 官网爬取 + 用户主动投稿（校内源当前无法触达）
- 载体：微信小程序；账号：微信授权登录
- 运营：单兵起步；AI 辅助审核（关键字段人工复核）；荣誉体系激励

**假设（上线验证）**
- 三痛点普遍存在；低年级有规划需求且愿意用工具；本校无同类多源工具
- 学生愿意投稿；用户愿意订阅提醒消息
- 灰色采集方案实测可用性；路线图内容可单人维护

**客观事实（不可改变的外部约束）**
- 微信不开放第三方读取公众号内容的能力（R9 根因）
- 小程序订阅消息需用户主动授权且一次性订阅有限制（R11 根因）
- 教务/学工系统封闭，无公开 API（R1 根因）
